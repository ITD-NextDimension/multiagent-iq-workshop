01怎么跑这个脚本

课程当天所有命令都在 WSL 的 Ubuntu 里敲——Lab 05 的部署脚本是 bash，PowerShell 跑不了。所以脚本第一件事就是把 WSL2 + Ubuntu 装上，这一步必须重启一次。只有这个体检脚本用 PowerShell。

  1. 1 第 1 遍 · 在管理员 PowerShell 里

    开始菜单搜 PowerShell → 右键 → 以管理员身份运行（装 WSL 需要），把 workshop-precheck-windows.ps1 存到「下载」文件夹，然后粘贴这一行回车。这一遍装的是 Windows 侧的东西：VS Code、四个扩展、WSL2 + Ubuntu。

    powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\workshop-precheck-windows.ps1" -Yes
  2. ⏻ 中间 · 重启，并给 Ubuntu 设个用户名密码

    脚本装完 WSL 会让你重启，这是正常流程，不是出错。重启后 Ubuntu 窗口会自己弹出来，让你设一个用户名和密码——它跟你的 Windows 账号无关，随便设一个记得住的即可（敲密码时屏幕上不显示任何字符，这是正常的）。

  3. 2 第 2 遍 · 同一条命令再跑一遍

    这一遍脚本会进到 Ubuntu 里面，装 Git、Python、课程依赖、az 和 kubectl，最后给你两行回执。

电脑本来就装好 WSL2 + Ubuntu 的同学，第一遍就会一次跑完，没有重启环节。反复运行是安全的，装到一半断了就重跑。

05Windows 上最常见的五个坑

  1. 把课程命令敲在 PowerShell 里——课程里的 .sh 脚本在 PowerShell 跑不了。只有这个体检脚本用 PowerShell，上课的所有命令都在 WSL 的 Ubuntu 里敲。 开始菜单搜 Ubuntu 打开终端，或在 VS Code 里 Connect to WSL 后用它自带的终端。
  2. 装完 WSL 没重启就继续——症状是脚本反复说「未安装发行版 Ubuntu」。 必须重启一次，并在 Ubuntu 窗口里设好用户名密码，然后重跑同一条命令。
  3. PowerShell 不是以管理员身份打开的——脚本会 WARN，然后装不了 WSL。 开始菜单搜 PowerShell → 右键 → 以管理员身份运行，重新跑一遍。
  4. VS Code 直接打开了 Windows 侧的文件夹——解释器、虚拟环境、依赖全对不上，报错千奇百怪。 一律用左下角 >< → Connect to WSL 打开项目。窗口左下角显示 WSL: Ubuntu 才算对。
  5. 公司电脑的网络策略——代理 / VPN / 证书拦截会让 pip 和 curl 直接失败，这是最常见的 NOT-READY 原因。 换个网络（手机热点最快）重跑一次，就能判断是不是网络问题。
