01怎么跑这个脚本

讲师会发两个文件，按你的电脑挑一个，另一个不用管。

macOS（和 Linux）

  1. 把 workshop-precheck-mac.sh 存到「下载」文件夹
  2. 打开「终端」（聚焦搜索 Terminal）
  3. 粘贴这一行，回车
bash ~/Downloads/workshop-precheck-mac.sh --yes

Windows

  1. 把 workshop-precheck-windows.ps1 存到「下载」文件夹
  2. 开始菜单搜 PowerShell，右键 → 以管理员身份运行
  3. 粘贴这一行，回车
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\workshop-precheck-windows.ps1" -Yes

Windows 会要求重启一次。课程当天所有命令都在 WSL 的 Ubuntu 里敲（Lab 05 的部署脚本是 bash，PowerShell 跑不了），所以脚本会先装 WSL2 + Ubuntu。装完它会让你重启电脑，重启后在 Ubuntu 窗口里设一个用户名和密码，然后把同一条命令再跑一遍。这是正常流程，不是出错。

参数什么时候用
--yes / -Yes推荐：全自动，不逐项问你
不加参数想知道每一步装了什么，逐项确认
--check-only / -CheckOnly只体检，一个字节都不装
--skip-azure / -SkipAzure暂时不装 Lab 05 的 az / kubectl

反复运行是安全的，装到一半断了就重跑。

05四个最常见的坑

  1. Windows 把课程命令敲在 PowerShell 里——课程里的 .sh 脚本在 PowerShell 跑不了。只有这个体检脚本用 PowerShell，上课的所有命令都在 WSL 的 Ubuntu 里敲。 VS Code 用左下角 >< → Connect to WSL 打开项目，否则用的是 Windows 侧的 Python。
  2. Windows 装完 WSL 没重启就继续——症状是脚本反复说「未安装发行版 Ubuntu」。 必须重启一次，并在 Ubuntu 窗口里设好用户名密码，然后重跑同一条命令。
  3. macOS 没装 Homebrew——脚本在 macOS 上靠它装东西，没有就只能报 FAIL。 先跑一次官网那条命令：/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/brew/HEAD/install.sh)"
  4. 公司电脑的网络策略——代理 / VPN / 证书拦截会让 pip 和 curl 直接失败，这是最常见的 NOT-READY 原因。 换个网络（手机热点最快）重跑一次，就能判断是不是网络问题。
