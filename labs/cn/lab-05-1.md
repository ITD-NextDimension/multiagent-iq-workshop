# Lab 05-1. 资源受限版：只部署 Web 应用

> [Lab 05](lab-05.md) 的替代方案，约 15 分钟。**做了 Lab 05 就不需要再做这一个。**

## 故事

完整的 Lab 05 会为每位学员创建 AKS、ACR、会话池、ACS Email 和监控。一个班同时开这些资源，
配额、成本和等待时间都会成为问题 —— 而且一旦某位学员的 AKS 卡在等公网 IP，整堂课的节奏就断了。

Lab 05-1 换一个分工：**重资源由讲师课前统一预置并共享，学员只部署自己的 Web 前端。**
学员依然完整体验一次 Container Apps 发布、HTTPS 入口和反向代理接线，但不碰 AKS、不用 `kubectl`，
也拿不到任何模型 Key 或 Kubernetes Secret。

## 架构

```text
你自己的 Container App（本实验唯一新建的资源）
  |  nginx 反向代理 /ask、/charts、/send-email
  v
共享 AKS: opc-agents API            ← 讲师维护
  |
  +-> Azure OpenAI / Foundry
  +-> MCP + dataIQ: 本体查询
  +-> Azure Communication Services Email

共享 Container Apps 环境 + ACR + 拉取身份   ← 讲师维护
```

学员的应用**没有**模型 Key、ACS 连接字符串或 Kubernetes 权限。它只知道一个后端地址，
其余全部由共享服务承担。

## 共享资源

以下全部由讲师在课前创建并维护，具体值写在讲师下发的 `workshop-web.env` 里：

| 资源 | 作用 |
|---|---|
| 资源组 | 所有共享资源和学员 Web App 都在这里 |
| Container Apps 环境 | 学员的 Web App 建在这个环境内 |
| 容器注册表（ACR） | 存放讲师预构建的 Web 镜像 |
| 用户分配托管身份 | 拥有 `AcrPull`，学员的 App 靠它拉镜像 |
| AKS 上的 Agent API | nginx 反向代理的后端 |

## 前置权限

讲师课前把一个**实验服务主体**配置为该资源组的 Contributor，并把客户端密码发给学员。
学员用它登录，全程不执行任何 RBAC 命令，也不需要个人 Azure 账号或 Portal 权限。

> 资源组级授权既能让订阅对服务主体可见，又把权限收在一个资源组内 ——
> 学员无法影响订阅里的其他资源。

## 实验步骤

1. 确认讲师发的 `workshop-web.env` 已经放到 [code/cloud/scripts/](../../code/cloud/scripts)
   目录下（和 `deploy-web-only.sh` 同级）。

2. 想好自己的应用名。**每位学员必须唯一**，建议用 `姓名缩写-web`：

   - 3–32 个字符
   - 只能用小写字母、数字和连字符
   - 字母开头，字母或数字结尾

3. 先预览一次，确认脚本会改什么、不实际部署：

   ```bash
   cd /workspaces/*/code/cloud/scripts && bash deploy-web-only.sh <你的应用名> --preview
   ```

   > 这是 Codespaces / Dev Container 里的绝对路径，在任何目录下都能直接粘贴。
   > 本地跑就把 `/workspaces/*/` 换成你自己的仓库目录。

4. 正式部署（约 1–2 分钟）：

   ```bash
   cd /workspaces/*/code/cloud/scripts && bash deploy-web-only.sh <你的应用名>
   ```

   脚本会隐藏输入让你粘贴服务主体密码，然后依次完成登录、共享资源预检、部署，
   最后打印你的 HTTPS 地址。

5. 打开输出的地址，依次提问验证：

   - `ACC-001 这个账户在给哪些项目付钱？`
   - `按项目状态汇总总预算，并画一张柱状图。`

   确认三件事：文字答案来自共享 AKS 上的 Agent API；图表能正常显示；
   浏览器地址栏始终是**你自己**的 Container App，而不是那个后端 IP。

6. 看一眼资源边界：

   ```bash
   az resource show -g <资源组> -n <你的应用名> \
     --resource-type Microsoft.App/containerApps \
     --query "properties.template.scale" -o json
   ```

   > 这里用的是 az 的**核心命令** `az resource show`，不是更常见的
   > `az containerapp show` —— 后者来自 `containerapp` 扩展，课堂容器里那个扩展
   > 不一定装得上（装扩展要用 az 自己解释器里的 pip）。两条命令读的是同一个
   > ARM 资源，输出一样。

   应该是 `minReplicas: 0`、`maxReplicas: 1` —— 这个上限由
   [code/cloud/web-only.bicep](../../code/cloud/web-only.bicep) 固定，学员改不了。

## 部署提醒

- 这个实验**只新建一个** Container App，其余资源都是 `existing` 引用。
  部署脚本可以反复执行，已存在的应用会按 Bicep 原地更新。
- 第一次打开页面会慢几十秒。`minReplicas=0` 意味着没有请求时副本会缩到零，
  这是冷启动，不是故障。
- **不要执行任何删除命令。** 共享资源组里有其他学员和讲师的资源，
  课后由讲师按应用名统一清理。
- 学员的应用通过托管身份拉取镜像，不使用 ACR 管理员用户名密码。

## 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `找不到共享资源配置 workshop-web.env` | 讲师发的配置文件没放对位置 | 放到 `code/cloud/scripts/` 下再重跑 |
| `workshop-web.env 里这些值还没填` | 拿到的是模板不是正式配置 | 找讲师要填好的版本 |
| `应用名 'xxx' 不合规` | 用了大写、下划线或长度不符 | 按第 2 步的规则改名 |
| 登录失败 | 密码粘贴带了空格，或服务主体未授权 | 重新粘贴；仍失败找讲师 |
| `看不到资源组` / 403 | 讲师尚未完成课前授权 | 联系讲师，**不要改用个人账号** |
| 名称已存在 | 和其他学员重名 | 换一个应用名重跑 |
| `共享资源不可用` | 共享服务异常 | **不要改脚本**，联系讲师恢复 |
| 首次打开很慢 | `minReplicas=0` 冷启动 | 等几十秒后刷新 |

## 小结

- 只部署 Web，同样完整体验了 ACA 发布、HTTPS 入口和反向代理接线
- 共享重资源能显著降低课堂的配额、成本和等待时间
- `minReplicas=0` / `maxReplicas=1` 是本实验明确的资源边界
- 最小权限：学员的应用没有模型 Key、ACS Secret，也没有任何 Kubernetes 权限
